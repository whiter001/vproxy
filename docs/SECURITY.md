# 安全策略（Security Policy）

## 报告漏洞

请**私下报告**安全漏洞，不要在公开 issue / 讨论区披露 0-day 细节。

首选渠道：

- GitHub：创建 **Private** issue（如仓库支持），标题注明 `[SECURITY]`；或在相关 issue 下用 Secret 评论（GitHub 2019 起支持 Secret 评论）。
- 邮件 / 私信：联系仓库维护者，说明这是 vproxy 的安全问题。

如果漏洞尚未修复，公开讨论会放大风险，请勿将细节发布到公开渠道。

## 报告内容模板

请尽量包含：

1. **版本**：`vproxy` 版本（`--version` 输出或 commit hash）、V 语言版本、操作系统。
2. **部署方式**：docker / 编译产物 / `v run`；监听地址与鉴权配置（是否开放代理、是否启用认证）。
3. **复现步骤**：最小 POC（命令、请求报文、环境变量），以及预期行为 vs 实际行为。
4. **影响评估**：能做什么（信息泄露 / 未授权访问 / 拒绝服务 / 其他）。
5. **可选修复建议**。

## 处理承诺

- 维护者会尽快确认并评估影响。
- 修复进入 main 后，将发布修复版本（release 流程见 `.github/workflows/ci.yml`）。
- 默认披露时间线为 **90 天**：修复发布后公开披露；如在 90 天内无法修复，会与报告者协商延期。
